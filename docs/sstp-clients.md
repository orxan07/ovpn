# Управление SSTP-клиентами

Во вкладке SSTP главный экран показывает клиентов, их подключения, текущую
скорость и измеренный трафик. Общие операции с портом, firewall, сертификатом,
логами и восстановлением вынесены в «Сервер и диагностика».

## Данные клиента

- Онлайн-статус и все текущие сессии одной учётной записи.
- Адрес клиента (`calling-sid`), адрес в туннеле, ID и длительность сессии.
- Загрузка и отдача, текущая скорость, MTU, ошибки и отброшенные пакеты
  интерфейса. Загрузка клиента соответствует TX сервера, отдача — RX.
- Расход по дням: сохраняются 90 дней, на экране отображаются последние 30.
- До 100 завершённых сессий; карточка показывает последние 20.
- Заметка, квота, срок доступа и состояние блокировки.
- Экспорт списка клиентов в CSV без паролей.

За одним SSTP-логином может находиться роутер с несколькими устройствами.
Панель учитывает такую учётную запись целиком; отдельные устройства за NAT
не идентифицирует.

## Учёт трафика

`server/sstp-monitor.js` снимает счётчики `/sys/class/net/sstp*/statistics`
каждые 5 секунд и сохраняет `data/sstp-monitor.json` каждые 30 секунд.
Файл записывается через временный файл с правами `0600` и rename.
Изменения настроек и сброс расхода сохраняются сразу.

Учёт начинается с первой успешной пары измерений. Расход до включения
сборщика не восстанавливается. Новая сессия получает новую базу счётчиков;
повторное подключение или сброс интерфейса не должны удваивать расход.
После перезапуска панели сбор продолжается по сохранённому снимку и ID
сессии. История и суточные интервалы используют часовой пояс Москвы.

Это измерение трафика PPP-интерфейса, а не биллинг провайдера. Последние байты
перед разрывом сессии могут не попасть в учёт; при аварии панели возможна
потеря последнего несохранённого интервала. Скорость появляется после второго
измерения. При сбое сбора интерфейс показывает ошибку и последний снимок.
Повреждённый JSON или неверная структура файла не перезаписываются автоматически.

## Доступ и настройки

Блокировка комментирует исходную запись в `chap-secrets` с префиксом
`# wg-admin-disabled:` и сохраняет её в base64 для разблокировки. Это обратимое
кодирование, не шифрование: файл авторизации и временные файлы закрыты правами.
Остальные записи, комментарии и дополнительные поля сохраняются.

После блокировки панель отключает все сессии пользователя. Если отключение
не удалось, новые подключения уже запрещены, а интерфейс сообщает об ошибке;
сборщик повторяет отключение активных сессий заблокированной записи.
Дубликаты логина нельзя изменять до устранения неоднозначности.

Квота задаётся в GiB и относится к сумме загрузки и отдачи с начала учёта или
последнего сброса. Квота и срок проверяются каждые 5 секунд работающей панелью;
это не жёсткий сетевой ограничитель. По достижении ограничения клиент блокируется.
Для возобновления доступа сначала увеличить/убрать ограничение или сбросить
расход, затем разблокировать клиента. Если панель остановлена, новые
ограничения не срабатывают; уже сохранённая блокировка остаётся в авторизации.

Отключение сессии не запрещает повторное подключение. Смена пароля не снимает
блокировку и не разрывает существующие сессии. Удаление клиента удаляет
реквизиты и учёт; повторное использование имени начинает учёт заново.

Фиксированный IP, ограничение скорости и индивидуальный маршрут пока доступны
только через настройку accel-ppp и сети. Для назначения IP через chap-secrets
нужно проверить `gw-ip-address` в секции `[chap-secrets]`, диапазон динамического
пула и одновременные подключения. Одного редактирования поля IP недостаточно.

## Активность

Карточка запрашивает последние 10 минут журнала sing-box, до 3000 строк.
Соединения связываются с текущими IP сессий по ID подключения в журнале;
записи до начала наблюдения за сессией отбрасываются. Отображаются назначения,
доступные sniffed-домены, TCP/UDP и outbound (`direct` / `outline`).

Это ограниченная выборка соединений через sing-box. Домен может отсутствовать,
прямой трафик в обход sing-box в выборку не попадает. Содержимое зашифрованных
запросов не показывается. Отсутствие строк не означает отсутствие трафика.
Журнал читается по требованию, результат кешируется на 10 секунд; интерфейс
сам не запрашивает его постоянно.

## API и проверки

Новые административные API защищены существующим Bearer-токеном:

- `GET /api/sstp/clients` — список и состояние сборщика;
- `PATCH /api/sstp/clients/:name` — `note`, `limitGb`, `expiresAt`;
- `POST /api/sstp/clients/:name/access` — `{ blocked: boolean }`;
- `POST /api/sstp/clients/:name/disconnect` — отключить все сессии;
- `POST /api/sstp/clients/:name/reset-usage` — обнулить расход;
- `GET /api/sstp/clients/:name/activity` — выборка соединений.

Новые API списка, настроек, доступа и активности, а также выдача реквизитов
возвращают `Cache-Control: no-store`. Список не содержит паролей.

Из корня репозитория:

```bash
node tests/sstp-backend.cjs
node tests/sstp-api.cjs
node tests/sstp-credentials-race.cjs
```

Проверки используют временные файлы и подставные команды, не изменяют VPN,
не запускают контейнеры и не требуют Express. Для визуальной проверки
использовался отдельный локальный стенд с синтетическими данными; это
не подтверждает совместимость установленной версии accel-ppp. Перед
выкладкой нужна проверка живого `accel-cmd show sessions` и прав сервиса.
